On a route

Tick "Show Caddyman's error pages" in the form of a route. When Caddy cannot answer for that route - the target is down, the visitor is outside the allowed networks, a file is missing - it fetches the page from Caddyman and sends it with the same status code. Errors a service sends itself are passed on untouched, and so is the login question of basic auth. {% if users %}Switched on for {{ users }} route{{ "s" if users != 1 }}.{% else %}No route uses them yet.{% endif %}

Where Caddy reaches Caddyman. Next to Caddy in the same Docker network that is the container name and port; from another machine, the address of this one. It is written into every route that shows error pages.

For a DNS blocker

Answers every name that no route knows with the Blocked page, over plain HTTP. In Technitium, choose the blocking type "Custom Address" and enter the IP address of the machine Caddy runs on. A blocked name then shows the page instead of a connection error. That only works for http://: for https:// Caddy has no certificate in the name of a blocked site, and the browser shows its own error.
