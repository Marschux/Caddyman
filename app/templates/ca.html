Windows

Paste this into PowerShell as administrator. The certificate is part of the command, so there is nothing to download. It asks for the check code and installs only if the code fits:

$cert = [Security.Cryptography.X509Certificates.X509Certificate2]::new([Convert]::FromBase64String("{{ der_base64 }}"))
$code = -join ([Security.Cryptography.SHA256]::Create().ComputeHash($cert.RawData)[0..5] | ForEach-Object { $_.ToString("X2") })
if (((Read-Host "Check code") -replace "[^0-9A-Fa-f]") -eq $code) { $store = [Security.Cryptography.X509Certificates.X509Store]::new("Root", "LocalMachine"); $store.Open("ReadWrite"); $store.Add($cert); $store.Close(); "Installed: " + $cert.Subject } else { "Wrong check code, nothing was installed." }

Or with the downloaded file. The path points at your download folder; change it if the file is somewhere else:

Import-Certificate -FilePath "$env:USERPROFILE\Downloads\root-ca.crt" -CertStoreLocation Cert:\LocalMachine\Root

Do not use the import wizard with "automatically select the certificate store": it files a CA under intermediate authorities of the current user, where Windows does not trust it and says nothing.

Debian and Ubuntu

Print the check code of the downloaded file first and compare it:

openssl x509 -in root-ca.crt -noout -fingerprint -sha256 | cut -d= -f2 | tr -d : | cut -c1-12
sudo cp root-ca.crt /usr/local/share/ca-certificates/root-ca.crt
sudo update-ca-certificates

The file name has to end in .crt.

Firefox

Firefox keeps its own list and ignores the system store by default. Either import it there: Settings, Privacy & Security, Certificates, View Certificates, Authorities, Import, and tick "Trust this CA to identify websites". Or let Firefox use the system store by setting this to true in about:config:

security.enterprise_roots.enabled

Back up the CA itself

This matters more than a backup of the routes. Routes are retyped in an hour; if the root key is lost, a new root has to be imported on every device again. Caddyman cannot back it up, because it lives {% if internal %}in Caddy's data volume{% else %}in the volume of your CA, not here{% endif %}. Adjust the volume name to your setup:

{% if internal %} 
docker run --rm -v caddy_caddy_data:/data -v "$PWD":/backup alpine \
  tar czf /backup/caddy-pki-backup.tar.gz -C /data/caddy pki
{% else %} 
docker run --rm -v stepca_stepca_data:/data -v "$PWD":/backup alpine \
  tar czf /backup/ca-backup.tar.gz -C /data .
{% endif %}

The archive contains the private key of the CA. Store it accordingly.
